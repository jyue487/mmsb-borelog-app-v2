# Python borelog integration

Bringing the Excel → borelog PDF printer — today a separate Python program — into this repo,
so the dashboard can do it.

## Vocabulary

To avoid ambiguity, from here on:

- **fieldlog** — the log `@mmsb/fieldlog` draws from the field app's blocks (the mobile
  "Share fieldlog" and the dashboard's "Download fieldlog"). Renamed from `@mmsb/report`, with
  `renderBorelogPdf` → `renderFieldlogPdf` and `downloadBorelogPdf` → `downloadFieldlogPdf`.
- **borelog** — the professional borehole log the Python program draws from a filled AGS
  workbook (`github.com/jyue487/mmsb_excel2borelog`, reportlab).

## Why

1. **No Windows licensing.** The Python program ships as a PyInstaller `.exe` (built by GitHub
   Actions on `windows-latest`) with per-PC activation (`app/licensing.py`, `app/device_id.py`,
   `license.lic`). In the dashboard, Supabase auth and member roles replace all of that.
2. **Web-based, not device-based.** Any admin with a browser and a connection can convert, from
   anywhere, with nothing to install.
3. **One place to change it.** A rule change like SPT50 → SPT100 ships with a dashboard deploy,
   instead of rebuilding and redistributing an exe to every licensed PC.

## Assessment

Sound, and cheaper than it looks, because the program lines up with what this repo already does:

- **Same coordinate system.** reportlab's canvas and pdf-lib both work in points, origin bottom
  left, y up. The ~900 lines of drawing port almost line for line.
- **Same font metrics.** The program draws in reportlab's `Helvetica`, one of the PDF standard-14
  fonts. pdf-lib's `StandardFonts.Helvetica` uses the same Adobe AFM widths, so string widths and
  therefore every line break come out identical, and there are no font files to ship.
- **Same xlsx tooling.** `fflate` is already a dependency of `@mmsb/ags-excel` and the dashboard.
  Reading a workbook is the inverse of `patchWorkbook.ts`. Reading each cell's cached `<v>` is
  exactly what `openpyxl.load_workbook(data_only=True)` does.
- **Runs in the browser.** Like the fieldlog, the whole thing can run client-side: no server, no
  edge function, the workbook never leaves the admin's machine. That makes role gating a pure UI
  concern — there is no data being served that RLS would have to protect.

Risks, and how they are handled:

- **reportlab `Paragraph` is not trivial.** Descriptions are wrapped and split across pages by
  reportlab's flowables. The port implements the subset actually used (greedy word wrap, leading,
  split at a height, `KeepInFrame` shrink, the `<para align>`/`<br/>`/`<b>`/`<font size>` markup)
  and is checked by pixel diff against the Python output (below).
- **Cached values only.** Like the Python program, the port reads what Excel last *cached*, never
  evaluating formulas — SPT's N value (`S`) and reported result (`T`) are formulas. A workbook
  saved by Excel, LibreOffice or our own AGS export (which writes correct caches) is fine; one
  generated by a tool that leaves formula caches empty is not, in either implementation.
- **Helvetica is WinAnsi-only.** pdf-lib throws on a character the standard font cannot encode,
  where reportlab drew a missing-glyph box. The port substitutes rather than throws.

## How the Python program works

`main.py` finds every `.xlsx`/`.xlsm` beside the exe (skipping `~$` lock files), and calls
`generate_borelog_pdf(openpyxl.load_workbook(f, data_only=True), name)` on each; a failure writes
`<name>.error.txt` instead.

### Sheets and cells read

Sheet names are matched after `strip()`. If both `SPT - AGS` and `SPT - AGS (2)` exist, the
`(2)` sheet wins. Missing any of the first seven below is an error; the last three are not read.

| Sheet | Rows | Columns read |
| --- | --- | --- |
| `Project - AGS` | fixed cells | name `D4`, id `I4`, client `D6`, engineer `D7`, location `D8`, contractor `D9`, date `D10`, remarks `D11` |
| `Holes - AGS` | **row 6 only** | `A` proj, `B` hole id, `C` type, `D` easting, `E` northing, `F` final depth, `G` ground level, `H` start, `I` end, `J` backfill date, `K` logger, `L` location, `M` general remarks |
| `Progress - AGS` | 6 → first blank `B` | `C` date, `D` time, `E` hole depth, `F` casing depth, `G` water level |
| `SPT - AGS` | **7** → first blank `B` | `C` test depth, `S` N value (cache), `T` reported result (cache) |
| `Geology - AGS` | 6 → first blank `B` | `C` geology code, `D` legend code, `E` top, `F` base, `G` description, `H` reference |
| `Samples - AGS` | 6 → first blank `B` | `C` top, `D` base, `E` type, `F` reference, `G` diameter, `H` recovery |
| `Core - AGS` | 6 → first blank `B` | `C` top, `D` base, `E` TCR, `F` SCR, `G` RQD, `H` diameter |
| `Water Strike` / `Detail Description` / `Backfill` | — | not used |

Percentages are fractions (`0.9` → `90`); dates may be real dates or `dmmyyyy`/`ddmmyyyy`
integers; times may be times or bare integers (`900` → `0900`). `utils/excel_input.py` holds
these rules.

### Drawing

One page per 9 m (1 tick = 0.1 m, 90 ticks a page, as in the fieldlog). Page count is
`ceil(last progress depth / 9)`, plus one if the last stratum's description does not fit on what
would otherwise be the last page. Each page draws, in order:

- **header** — company logo, "DEEP BORING LOG", project no, borehole no + "Sheet n of N", project
  name and location (shrunk to fit), dates, co-ordinates, client, hole type, level;
- **ProgressDrawer** — date/time and water level at each shift boundary, starts below the line
  and ends above it;
- **GeologyDrawer** — legend pattern PNG tiled down the legend column (`assets/legends/<code>.png`,
  falling back to `999.png`), and the stratum description, pushed down past the previous one if
  they collide (the diagonal "extended" lines), split across pages when it overflows, plus the
  dashed "End of Borehole at x.xx m";
- **CoreDrawer** — TCR and RQD at each core run's top;
- **SampleDrawer** — depth, type and recovery for every sample. A `D` sample is an SPT and takes
  the *next* row of the SPT sheet, in order, for its result; a `C` sample draws the core-run box;
- **column header, body grid, depth scale**;
- **SptGraphDrawer** — N value plotted on a 0–50 axis, points joined in blue;
- **footer** — remarks (last page only, shrunk to fit), "Continued next sheet", stamp, "Logged By".

### Quirks preserved in the first TypeScript version

The first version is an exact replica, so it can be proven against the Python output. These are
carried over deliberately and fixed afterwards (follow-up 5):

- "Logged By" is hardcoded `IZWAN`; Holes `K` (logger) is read but unused.
- "Hole Type" is hardcoded `Rotary`; Holes `C` is read but unused.
- The SPT graph axis ends at N = 50, so an SPT100 project's N > 50 plots past the column.
- SPT results are paired with `D` samples by order, not by depth.
- Descriptions are reportlab markup, so `<i>`, `<b>` and entities in a cell are interpreted.

Not carried over: device licensing, the `.error.txt` files (the UI reports errors instead), and
directory scanning.

## Target design — `packages/borelog` (`@mmsb/borelog`)

**Built** (`packages/borelog`). A sibling of `packages/fieldlog` and `packages/ags-excel`, with the same shape as the
latter: raw TypeScript (`main`/`types`/`exports` → `./src/index.ts`), and **platform-free** —
`tsconfig.json` has `lib: ["ES2020"]` and no node or DOM types, so the package runs unchanged in
the browser and in Node. Hosts hand in bytes and get bytes back.

```
src/
  xlsx/readWorkbook.ts     unzip (fflate) → sheets by name, shared/inline strings, cached
                           values, and openpyxl's own date detection from styles.xml
  xlsx/cellConvert.ts      utils/excel_input.py
  py/number.ts             Python's round(), f'{x:.2f}', str(float), float(), int()
  parse/parseSheets.ts     parsers/*.py, same cells
  parse/parseBorelogWorkbook.ts
                           → { project, boreholes[], borelogData(holeId) }: every Holes row,
                           every other sheet grouped by hole id (column B)
  render/canvas.ts         the reportlab Canvas calls the program makes, over a pdf-lib page
  render/paragraph.ts      reportlab's Paragraph and KeepInFrame(shrink), from its source
  render/config.ts         constants/config.py
  render/drawHeader.ts, drawBody.ts, drawers.ts
                           draw_header.py, draw_body.py, drawers/*.py — line for line
  renderBorelog.ts         generate_borelog_pdf.py: (BorelogData, assets) → PDF bytes
assets/                    company_logo.png, footer_logo.png, legends/*.png (202)
scripts/                   render (xlsx → PDFs in Node), compare (against the Python program)
```

Grouping by hole id costs nothing on today's single-hole workbooks — the output is the same — and
is what follow-up 2 needs. Output is deterministic (`CreationDate`, `ModDate`, `Producer` and
`Creator` pinned, as in `packages/fieldlog`), so identical input hashes identically.

## Verification

Done, and rerunnable. There is no test runner, and the goal is "prints what the Python program
printed", so the check is differential, against the Python program itself, three ways:

```bash
MMSB_EXCEL2BORELOG=~/Desktop/mmsb_excel2borelog PYTHON=<python with reportlab, openpyxl, pillow> \
  pnpm --filter @mmsb/borelog compare
```

| Check | Against | Result on the six sample workbooks |
| --- | --- | --- |
| parse | every field of every row the Python parsers read | 0 differences |
| paragraph | reportlab's line breaks, heights, page splits and shrink scales, 3,213 cases | 0 differences |
| pixels | every page of every borelog, rasterised by Ghostscript at 200 dpi | page counts equal; 2 pixels differ in all 37 pages, both inside SPT graph dots |

The samples are real client workbooks and stay out of git: copy them into
`packages/borelog/samples/` (gitignored). Output is deterministic — two renders of the same input
are byte-identical.

### Where the port deliberately differs

All of these are cases where the Python program crashed or printed something wrong; none occurs
in the sample workbooks.

- A bare `&` in text prints as `&`. reportlab's markup parser turned `G&P` into `G&P;`.
- An unknown tag in a description (`<abc>`) prints as text. reportlab failed the whole workbook.
- A character Helvetica cannot encode prints as `?`; a line break typed into a single-line cell
  is dropped. reportlab drew an empty box.
- A hole with no Progress or Geology rows gets a clear error naming it. Python raised `IndexError`.
- A workbook with several holes: each hole's borelog takes only its own rows. Python drew the
  hole on row 6 with *every* row of every sheet. With one hole the two are identical.
- An empty percentage cell typed as text (`""`) prints empty. Python raised `IndexError`.
- Two consecutive `<br/>` straddling a page break split one line differently. Typed Excel text
  cannot contain `<br/>`.

Two Python quirks to know about, kept because the replica keeps everything: a missing progress
time prints as `None` (`dd/mm/yyyy None`), and an empty description on the last stratum adds a
blank final page.
